# 本地体检与验证记录

日期：2026-10-05。范围：`apitester` 的代码检查、测试、依赖检查、Windows 构建与打包，以及程序和独立数据目录、仓库的统一改名；没有修改服务器。

## 本轮修复

- HTTPS/WSS 原来默认跳过证书校验，curl 导出也无条件带 `-k`。现在默认校验，测试自签名服务需要显式启用不安全选项，并保存对应请求的 TLS 设置。
- WebSocket 发送缺少单写者保护，增加发送锁和 10 秒写入超时。
- 为旧拨号结果、旧连接清理增加保护，防止断开或重新连接后覆盖当前状态。
- HTTP `Host` 在 Go 中是特殊字段，原来仅设置 Header 不生效；现在实际发送并记录。
- HTTP 消息现在记录独立快照，避免后续响应更新修改已保存的请求消息；清除 Cookie 时替换客户端，不修改进行中的客户端。
- 前端锁文件更新 nanoid、PostCSS。项目工具链由 Go 1.26.5 升为 1.26.6，解决检查发现的 [GO-2026-6090](https://pkg.go.dev/vuln/GO-2026-6090) 和 [GO-2026-5972](https://pkg.go.dev/vuln/GO-2026-5972)。没有替换系统全局 Go。
- 默认数据目录统一为 `apitester-data`，移除旧名称兼容和自动迁移逻辑；本机目录、位置记录及独立仓库名称同步更新，数据仓库仍为私有。
- 选目录取消或失败时不保存默认位置，避免后续启动跳过选择。
- 程序仓库和本地目录统一为 `apitester`，同步 Go 模块、文档链接、打包脚本、私有数据测试环境变量和本机数据位置记录；显示名称及可执行文件名仍为 `ApiTester`。为保持已有设置和导出文件可用，内部存储键与目录文件格式标识不改动。

## 验证结果

- Go 1.26.6 / Node.js 24.18.0 / Windows amd64。
- 67 个常规 Go 测试及 1 个可选私有数据测试通过；`go test -race -count=3 ./...` 通过。未提供私有数据目录时，可选测试跳过。
- `go vet ./...`、`go mod verify` 通过。
- 6 个前端测试通过；Vite 生产构建通过。
- `npm audit` 报告 0 项漏洞。
- `govulncheck v1.8.0` 未发现本程序可达的已知漏洞。
- GitHub Actions 配置通过 actionlint v1.7.7 检查；打包脚本通过 PowerShell 语法检查并实际运行。
- Wails v2.13.0 生产构建成功；输出 Windows exe、ZIP 和 SHA-256 校验文件。
- 下载包允许列表检查通过，仅包含 exe、使用说明、更新记录、第三方说明及 38 份许可文件，无项目配置或请求日志。
- 当前仓库及原有 19 个 Git 提交的常见私钥、GitHub Token、AWS Access Key 格式检查未发现匹配项。这不是完整的秘密检测或安全审计，不能排除自定义密码、任意格式 Token 或其他敏感数据。

## 独立私有数据验证

补充运行了可选的离线兼容性测试：4 个项目、24 个接口、4 个环境和 4 份历史文件均可读取，项目保存后接口、环境和 TLS 偏好保持一致；原数据文件的 SHA-256 校验未变化。保存操作只发生在临时副本，不向真实接口发送请求。

测试通过 `APITESTER_TEST_DATA` 指定数据目录，源码不包含私有数据、接口地址或数据仓库链接。未设置该环境变量时跳过，公共 CI 不需要私有仓库权限。

## 尚未验证或处理

- GitHub 的实际构建结果以 Actions 页面为准，本地验证不代替云端构建；本轮没有创建版本标签或正式发布 Release。
- 没有实际操作桌面图形界面进行人工验收，因此尚未补真实界面截图、演示视频。后端网络回归使用本地 HTTP/HTTPS/WS/WSS 测试服务器，不等同于界面验收。
- 没有执行来源不明的外部接口，也没有使用真实生产凭据。
- Windows 下载包尚未代码签名；项目自身的开源许可尚未指定，没有擅自添加 MIT 等许可。
- 项目数据和日志仍然明文存储，应由用户限制访问并在分享前脱敏。
